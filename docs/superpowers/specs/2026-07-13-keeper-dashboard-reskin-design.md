# Keeper League Dashboard — Pick'em-Style Reskin

**Date:** 2026-07-13
**Status:** Approved design, ready for planning
**Scope:** Visual reskin + light UX polish of the generated league-history dashboard

---

## 1. Goal

Reskin the static league-history dashboard produced by `dashboard.py` to match the
look and feel of the `nfl_pickem_app` "Sleeper-style" redesign: deep charcoal
surfaces, a primetime-gold accent, Archivo + Manrope type, card-based layout, and an
app-like navigation. Add small, opportunistic UX improvements (mobile layouts,
hero champion card, mobile head-to-head) but **no new data and no new stats.**

## 2. Current state

- One self-contained `docs/<slug>/index.html` per league is generated by
  `build_dashboard(seasons, output_path)` in [dashboard.py](../../../dashboard.py)
  from a big `_HTML_TEMPLATE` format string (inline `<style>` + vanilla JS + the
  computed stats injected as a single JSON blob).
- Five sections, switched client-side: **All-Time Standings · Champions ·
  Head-to-Head · Player vs Player · Records.**
- Current look: GitHub-dark (`#0d1117` bg, blue `#58a6ff` accent, system fonts,
  centered horizontal tab row). Tables sort client-side; some rows expand.
- Generated by: `python main.py dashboard <league_id> <slug> --provider <p>`, which
  (absent `--refresh`) loads the cached `<slug>_history.json` and calls
  `build_dashboard`. Cached history exists for all four leagues
  (`wheaton`, `hey`, `lobos`, `espn-test`), so the reskin can be regenerated and
  reviewed **fully offline**.

  (inline CSS/JS, stats as JSON) — no other external assets.
- Tabular numerals (`font-feature-settings:'tnum'`) for all stat numbers.

## 4. Section-by-section design

### 4.1 Header + navigation (hybrid)
- Sticky top bar: gold brand-mark (rounded square + trophy/football glyph) +
  league name + a season-range chip (e.g. `2005–2025`).
- Section nav is **responsive hybrid**:
  - **Desktop (≥720px):** a row of gold pill tabs (active = filled gold pill).
  - **Mobile (<720px):** a fixed bottom tab bar (icon + short label per section,
    gold active color + top indicator bar). With 5 sections, labels are short
    (`Standings · Champs · H2H · vs · Records`).
- Existing vanilla-JS `show(section)` tab switching is retained; both the desktop
  pills and the mobile tab bar drive/reflect the same active-section state.

### 4.2 All-Time Standings
- Leaderboard table inside a card: rank (gold for #1), colored initial-avatar,
  manager name (crown icon for champions), then W–L, win %, titles, PF, PA,
  playoff appearances (same columns as today).
- Leader row gets a subtle left-to-right gold-glow wash.
- Retain client-side **sortable columns** (restyle the sort affordance: gold
  active header + arrow) and the **expandable per-manager season detail** rows
  (restyled inner table).

### 4.3 Champions — "Reigning champ + timeline" (chosen: Option A)
- A glowing **hero card** for the most recent champion: gold-bordered, gradient
  wash, trophy tile, big manager name, team name in gold, and a meta line
  (regular-season record · who they beat in the final · Nth title).
- Below it, a **year-by-year timeline** list: year · avatar · manager · team ·
  title-count badge, one row per season, most recent first.

### 4.4 Head-to-Head — responsive (chosen: Option B on mobile)
- **Desktop:** the full color-coded matrix (managers × managers), cells tinted
  by record strength (success green → danger red, dim for even), first column
  sticky, horizontal scroll if needed.
- **Mobile (<720px):** collapses to a **"pick a manager → vs everyone" list** — a
  selector pill for the focal manager and a list of opponents (avatar, name,
  all-time record, and an `Owns / Leads / Even / Trails` tint pill). Switching the
  focal manager re-renders the list. Both views are driven from the same H2H data
  already computed; the mobile list is derived from the matrix rows.

### 4.5 Player vs Player
- Reskin only; behavior unchanged. A "versus" header (two initial-avatars +
  each manager's overall record and their head-to-head record) over the existing
  matchup-history list. Keep the two existing manager selectors (styled as pill
  selects).

### 4.6 Records
- Render the existing record stats (biggest blowout, highest/lowest score,
  longest win/lose streak, nemesis pairs, etc.) as **pick'em-style stat cards** in
  a responsive grid (`1fr` → `1fr 1fr`). Keep the existing **expandable top-N
  lists** inside each card, restyled.

### 4.7 Filters / selectors
- Any season/manager `<select>` filters restyled as the pick'em **gold pill-select**
  (custom chevron, pill radius, uppercase label).

## 5. Interaction / JS notes
- Keep the current vanilla-JS approach (no framework, no build step). Work is in
  the markup the JS emits and the CSS class names, plus:
  - sync active state between desktop pills and mobile tab bar,
  - a media-query-driven branch for H2H (matrix vs mobile list) + a focal-manager
    switch handler for the mobile list,
  - a focal-manager selector for the PvP "versus" header (already selector-driven).
- Respect `prefers-reduced-motion` (disable the entrance/transition animations),
  matching the pick'em stylesheet.

## 6. Accessibility posture
- **AA color contrast** comes for free by adopting the pick'em palette (its text
  tiers are contrast-checked on `--bg`).
- Keep `:focus-visible` outlines and sensible semantics (real `<table>`s,
  buttons for tabs).
- **Out of scope:** screen-reader/ARIA hardening, keyboard-tablist semantics, skip
  links — the keeper audience is fully sighted (explicit decision). This is the one
  place this dashboard intentionally does *less* than the pick'em app.

## 7. Non-goals / guardrails
- No new data, stats, sections, or provider changes.
- Python stat-computation functions in `dashboard.py`
  (`_compute_*`) and the `main.py` CLI are **not** modified (except that
  `build_dashboard` continues to receive the same `stats` dict / JSON shape).
- One template powers all four leagues; no per-league styling.
- No server, no database, no framework — output stays a single static HTML file.

## 8. Files touched
- `dashboard.py` — rewrite `_HTML_TEMPLATE` (the `<style>` block, the header/nav
  markup, and the JS that renders each section) to the new design. The
  `build_dashboard` signature and the injected `stats`/`data_json` shape are
  unchanged.
- `.gitignore` — add `.superpowers/` (brainstorm scratch). *(done)*
- Regenerated outputs: `docs/{wheaton,hey,lobos,espn-test}/index.html`.

## 9. Regeneration & verification
- Regenerate each league from cache (no network):
  `python main.py dashboard <id> <slug> --provider <p>` — or, since it just loads
  the cache, a small loop over the four slugs.
- Verify by opening each `docs/<slug>/index.html`:
  - all five sections switch (desktop pills + mobile tab bar),
  - champion hero + timeline render with real data,
  - H2H shows matrix on wide viewport and the pick-a-manager list on narrow,
  - sortable columns and expandable rows still work,
  - spot-check a couple of numbers against the current dashboard to confirm the
    reskin changed presentation only, not values.
- Check both a wide window and a ~375px-wide window (responsive breakpoints).

## 10. Risks
- **Template size:** `dashboard.py` is one large format string; a big rewrite risks
  Python `str.format` brace-escaping bugs (`{{ }}`). Mitigate by regenerating and
  loading the HTML after the change (a broken template fails fast).
- **H2H mobile branch** is the only genuinely new interaction; keep it derived from
  existing matrix data so it can't disagree with the desktop view.
